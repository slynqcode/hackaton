# Записка о дизайне AuditForge

## 1. Идея
Жюри оценивает **корректность среды и оценщика**, а не награду агента. Поэтому среда спроектирована так, чтобы каждое её
утверждение было *проверяемо машиной*: «до ошибки книги сходятся», «после — расхождение ровно объявленное», «доказательств
достаточно», «ответ не зависит от порядка/ID/часовых поясов», «оценщик ловит свои поломки». Эти проверки — часть продукта.

## 2. Конвейер данных
```
seed+config ─► история (контрагенты, счета, платежи, ряд FX)         [generator.build_history]
            ─► ЧИСТЫЕ книги = render(история, ошибок нет)            [инварианты учёта выполнены]
            ─► план ошибок (операторы мутаций, причинные связи)       [generator.plan_faults]
            ─► книги с ошибками = render(история, ошибки)
            ─► provenance = diff(чистые, с ошибками) + параметры операторов + causal_links
            ─► truth = типы, affected_ids, ожидаемая сумма, валюта, допустимые наборы доказательств
```
* Идентификаторы строятся от ключа (`sha256(seed|kind|key)`), а не от порядка вызовов, поэтому чистый и «грязный» рендеры
  согласованы, а ID не несут информации об ошибках. Порядок документов — псевдослучайный, но не зависит от ошибок.
* Время хранится как моменты; в записях выводится в случайных UTC-смещениях (≠ смещению компании) — ловушка для сравнения дат-строк.
* Деньги — `int` в минимальных единицах (`currency_exponents` в manifest: USD 2, JPY 0 …), курсы — десятичные строки (10 знаков),
  округление — один раз в валюте результата (`half_up` | `half_even`, выбирается эпизодом).

## 3. Операторы мутаций и эталон
| Оператор | Изменение | `expected_amount_minor` | Валюта |
|---|---|---|---|
| `duplicate_invoice` | +счёт-копия (новые ID, сдвиг даты, строки перемешаны) с проводками | итог счёта | валюта счёта |
| `payment_allocation` | `invoice_refs` частично/`null`; остаток → `UNAPPLIED` | платёж − Σ распределённого | валюта платежа |
| `fx_error` | AR/FX_CLEARING по курсу другой даты или с опечаткой | \|проведено − верная конвертация распределённой части\| | валюта счёта |
| `period_cutoff` | время проводки переносится на другую сторону границы периода | итог счёта / \|платёж\| | валюта документа |

Эталон описывает реальное расхождение и *доступные* доказательства: каждый допустимый набор перепроверяется слепым решателем,
который видит только перечисленные записи + manifest/policy (`checks.solve_from_evidence`).

**Взаимодействия.** `partial_fx`: платёж в валюте, отличной от валюты счёта, у границы периода (локальное время сразу после
полуночи → UTC-дата вчерашняя), частично распределён; конвертация применена к *распределённой* части по *UTC-дате*. Наивный
расчёт «весь платёж по дате из строки» даёт неверную сумму. `cutoff_fx`: платёж проведён за границей периода, система
конвертировала по дате проведения; две ошибки связаны причинно (`causal_links`).

## 4. Среда
* `reset(seed, config) → (obs, info)`; `step(action) → (obs, reward, terminated, truncated, info)`; JSON-совместимо.
* Действия: `list_records` (≤50 строк, курсор `c<offset>` стабилен), `get_record`, `get_document`, `calculator` (свой разбор:
  `+ - * /`, скобки, десятичные; без имён, вызовов, `**`), `submit`.
* Любое действие (в т.ч. ошибочное) тратит шаг; ошибки — фиксированные коды/сообщения, не эхо состояния оценщика.
* 100 шагов включая `submit`; исчерпание шагов/60 с → `truncated=True` и *пустой* итоговый ответ оценивается обычной формулой.
* `mode="train"`: терминальная награда и счётчики TP/FP/FN в `info`; `mode="eval"`: `reward=0.0`, `info={"step":n}`, результат читает только
  харнес через `env.evaluation()` после конца прогона. Подсказок о правильности по ходу нет.
* Изоляция: оценщик (truth, grader) живёт в `server.py` отдельным процессом; `RemoteEnv` общается JSON-строками;
  stderr процесса оценщика отброшен; наблюдения — глубокие копии.

## 5. Награда и устойчивость к «взлому» (specification gaming)
Награда зависит только от структурированных полей и доказательств. Атаки и ответ матчера:
пометить всё → много FP, F1≈0; дубли → FP; угаданные ID/чужие доказательства/не та валюта/сумма вне допуска → не TP;
повторный `submit` → `episode_finished`, результат не меняется; текст `explanation` не влияет; порядок выводов не влияет;
экономия шагов меняет награду на 0.002 за шаг (при 100 шагах ≤ 0.2 — не переворачивает правильный/неправильный ответ).
Матчер — максимальное паросочетание (алгоритм Кёна), а не жадное: тест-ловушка специально убивает жадную реализацию.

## 6. Как проверяется сама среда
1. **Сертификат эпизода** (`certificate.certify`): чистые книги восстанавливаются из provenance обратным применением diff и
   проходят инварианты (Дт=Кт по группе и валюте, итоги счетов, полное распределение, конвертация по политике, сторона периода,
   нет дублей); «идеальный детектор» находит на грязных книгах **ровно** truth; все наборы доказательств достаточны; id существуют;
   нет утечек словаря оценщика в публичные файлы; форматы; размеры.
2. **Парные проверки**: перестановка строк, смена ID (включая memo и ссылки), смена смещений времени, всё вместе — oracle и
   `reference_solver` получают тот же результат; «старый» ответ со старыми ID на переименованном эпизоде не даёт TP.
3. **Побитовый повтор**: тот же seed/config → те же таблицы, truth, provenance и траектория.
4. **Мутационное тестирование оценщика**: 38 осознанных поломок matcher/награды/валидации; каждая должна провалить хотя бы одну проверку.
5. **Контракт/изоляция**: 32 проверки (страницы, курсоры, ошибки, лимиты, завершение, copy-on-read, отсутствие утечек, процесс оценщика).
6. **Политики организаторов** на 20 «скрытых по духу» эпизодах (5 чистых, 5 с взаимодействиями) в изолированном режиме:
   случайный исследователь, простая сверка, «пометить всё», oracle (+`reference_solver`, доказывающий решаемость только через API).
7. **Измеренный разбор сбоев** (`reports/failure_analysis.md`): абляция по отвлекающим случаям и по «наивным» сокращениям простой сверки.

## 7. Версия 1.1: защита от взлома (подробно docs/RISKS.md)
* **Ошибки внутри отчётного периода (v1.3.2).** Независимые дубли, ошибки разнесения и курса ставятся только на документы внутри [period_start, period_end): аудитор не засчитал бы майский дубль в проверке марта–апреля. Исключение по замыслу кейса: сценарии взаимодействия «платёж в другой валюте на границе периода», где документ стоит в нескольких часах от границы.
* **Сломанное сообщение = неверное действие (v1.3.2).** Нечитаемая строка или неизвестная операция во время эпизода тратит шаг, как неизвестное действие.
* **Секрет оценщика (v1.2–1.3).** Открытый генератор + seed позволяли восстановить эпизод. Теперь `eval` в изолированном оценщике всегда работает с секретом: секрет организаторов или случайный, созданный внутри процесса оценщика. Секрет приходит первой строкой stdin (без файлов, командной строки и окружения); `train` не читает его из окружения; режим и лимиты задаются только при запуске оценщика; в `eval` один процесс = один эпизод; итоговая оценка идёт по отдельному каналу обвязки.
* **Доказательства обязаны существовать.** ID, которого нет в эпизоде, делает вывод несопоставимым.
* **Авансы.** Законная строка `UNAPPLIED` без счёта ломает трюк «UNAPPLIED = ошибка»: нужно читать memo и `invoice_refs`.
* **Фаззер награды** (`fuzz.py`): случайные ответы из возмущённых верных выводов и «мусора» из реальных записей;
  каждая выданная TP перепроверяется независимым предикатом, награда не может превысить oracle; слепое угадывание по открытым
  записям остаётся на −1.
* **Отчёт по эпизоду** (`explain.py`): что сломано, как увидеть, где ловушки, граф причин в Mermaid.

## 8. Что сознательно не сделано
Обучение весов, UI, реальные данные, DST/tzdata, триангуляция валют, налоги. См. «Limitations» в README.

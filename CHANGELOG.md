# Changelog

## 1.3.1 (ловушки против простых правил)
- Новые законные ловушки: ранние проводки (до 20 ч до документа), поздние проводки 5 ч – 4 дня, частичная поставка на ту же сумму с другими позициями, авансы с `invoice_refs = null`, переплата с остатком «на счёте как предоплата».
- `auditforge/tricks.py` и таблица в `reports/failure_analysis.md`: 6 правил-обходов, каждое даёт от 40 до 200 ложных обвинений на 60 эпизодах; `tests/test_tricks.py` следит за этим.
- Конфигурация, дающая больше 200 документов, отклоняется с понятной ошибкой; каждая ловушка ≤ 12.
- 194 теста.

## 1.3.0 (по итогам второго независимого ревью)
- Секрет передаётся оценщику первой строкой stdin: без временного файла (его можно было прочитать, пока он существовал) и без пути в командной строке.
- `verify` и `demo.py` по умолчанию берут случайный секрет; фиксированный включается только явно.
- `RemoteEnv` в режиме `train` не читает секрет из окружения обвязки.
- Итоговая оценка уходит по отдельному каналу обвязки; в `eval` запрос `evaluation` от агента отклоняется (`harness_only`).
- Неверная конфигурация в `reset` даёт `bad_config`, а не `internal_error`.
- 31 проверка контракта/изоляции (было 28), 192 теста (было 189).

## 1.2.0 (по итогам независимого стресс-ревью)
Защита оценщика
- `eval` в `RemoteEnv` всегда работает с секретом: свой файл организаторов (`AUDITFORGE_SECRET_FILE`) или случайный, созданный внутри оценщика. Восстановление эпизода по `episode_id` или перебором seed больше не работает.
- Секрет передаётся через временный файл 0600 и не попадает в окружение процесса оценщика (`/proc/<pid>/environ`).
- Режим и лимиты задаются только при запуске оценщика; `reset` с `mode`/`limits` отклоняется. В `eval` один процесс = один эпизод.
Устойчивость
- Курсор `list_records`: только ASCII-цифры, не больше 9 (раньше `c²` и курсор из 5000 цифр роняли среду).
- `reset` проверяет seed (целое ≥ 0); калькулятор принимает только ASCII-цифры.
Данные
- Новые законные ловушки: частичные поставки по одному заказу и поздние проводки внутри периода. Простые правила «тот же po_ref» и «задержка проводки > 4 ч» теперь дают десятки ложных обвинений.
- Эпизоды перегенерированы; удалены 40 устаревших копий v1.0/v1.1 из `episodes/`.
Инженерия
- Dockerfile больше не зависит от `make`.
- 28 проверок контракта/изоляции (было 24), 189 тестов (было 185).

## 1.1.0
Исправления (подробно: docs/RISKS.md)
- Секрет оценщика `AUDITFORGE_SECRET` закрывает восстановление эпизода перебором seed.
- Доказательство с несуществующим ID больше не засчитывается.
- Новый законный отвлекающий случай: авансы (UNAPPLIED без счёта); трюк «любой UNAPPLIED» больше не работает.
- Генератор не падает на малом числе контрагентов; конфигурации валидируются; документов не больше 200.
- Опубликованные курсы никогда не правятся задним числом.
- `limit: null` в `list_records`; явная ошибка при падении процесса оценщика.

Новое
- `auditforge/fuzz.py`: фаззер взлома награды (корректность наград, слепое угадывание, атака перебором seed).
- `auditforge/explain.py`: отчёт по эпизоду для человека с графом причин (Mermaid), `episodes/*/*/evaluator/explain.md`.
- Диагностическая политика `zero_agent` («всегда молчать»).
- Проверок: контракт 24, награда 34, мутантов 38, фаззер в `make verify`.

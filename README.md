# AuditForge — воспроизводимая RL-среда для ИИ-аудитора

Синтетическая компания → скрытая история → документы и проводки с **записанными причинными ошибками** →
среда `reset/step` с узким набором инструментов → общий matcher и терминальная награда.
Среда **не обучает** модель и не заявляет улучшений; она даёт повторяемые взаимодействия, траектории и оценку.
Всё вымышлено. Только стандартная библиотека Python (без сети, платных API и GPU).

## Одна команда проверки

```bash
make verify            # = python -m auditforge.cli verify  &&  python -m pytest -q   (≈ 1 мин, 2 CPU)
```

Или в контейнере (сборка с сетью, запуск без сети; сборку мы не проверяли): `docker build -t auditforge . && docker run --rm --network none --cpus 2 --memory 4g auditforge`

`verify` печатает **самооценку** по рубрике кейса (контракт/изоляция, данные/эталон, надёжность награды, воспроизводимость,
инженерия), пишет `reports/scorecard.json` и завершается с кодом ≠ 0 при любом провале.

## Что внутри

| Путь | Назначение |
|---|---|
| `auditforge/generator.py` | история компании → чистые книги → план ошибок (операторы мутаций) → книги с ошибками, `truth`, `provenance` |
| `auditforge/env.py` | `AuditEnv.reset(seed, config)` / `step(action)` — JSON-контракт в стиле Gymnasium, лимит 100 шагов |
| `auditforge/server.py`, `remote.py` | оценщик в **отдельном процессе** (JSON-lines), агент видит только наблюдения |
| `auditforge/grader.py` | общий matcher (максимальное паросочетание 1-к-1) и награда `clip(2·F1−1−0.002·steps, −1, 1)` |
| `auditforge/checks.py` | независимые проверки: инварианты учёта, «идеальный детектор», слепой решатель по доказательствам |
| `auditforge/certificate.py` | сертификат корректности каждого эпизода |
| `auditforge/transforms.py` | безвредные преобразования: порядок, переименование ID, смена часовых поясов |
| `auditforge/mutants.py` | мутационное тестирование оценщика (38 мутантов) |
| `auditforge/fuzz.py` | фаззер взлома награды: корректность наград, слепое угадывание, атака перебором seed |
| `auditforge/explain.py` | отчёт по эпизоду для человека с графом причин (Mermaid) |
| `auditforge/policies.py` | 4 базовые политики + `reference_solver` + диагностическая `zero_agent` |
| `auditforge/selfchecks.py` | опубликованные фиксированные проверки (используются pytest и `verify`) |
| `configs/` | версионированные конфигурации: `train.json`, `dev.json`, `hidden_like.json` |
| `episodes/` | 10 открытых train и 10 dev эпизодов (`public/` — что видит агент, `evaluator/` — truth, provenance, certificate, explain.md) |
| `trajectories.jsonl` | траектории 5 политик на 10 train-эпизодах (без эталона в наблюдениях) |
| `reports/` | `scorecard.json`, `baselines.json`, `hidden_like_eval.json`, `mutation_report.json`, `failure_analysis.md` |
| `docs/DESIGN.md` | записка о дизайне |
| `docs/RISKS.md` | найденные и исправленные проблемы, прогноз ошибок у жюри |
| `CHANGELOG.md` | история версий |
| `schemas/` | JSON Schema для findings, действий и truth |

## Запуск вручную

```python
from auditforge.env import AuditEnv
env = AuditEnv(mode="train")                 # "eval": награда скрыта до конца прогона
obs, info = env.reset(seed=42, config={"interactions": ["partial_fx", "cutoff_fx"]})
obs, reward, terminated, truncated, info = env.step({"action": "list_records", "table": "ledger", "limit": 50})
obs, reward, terminated, truncated, info = env.step({"action": "calculator", "expression": "1250000*0.92"})
env.step({"action": "submit", "findings": {"episode_id": info["episode_id"], "findings": [...]}})
```

Изолированный режим (оценщик вне процесса агента): `from auditforge.remote import RemoteEnv` — тот же API.
Команды: `python -m auditforge.cli {gen|baselines|analysis|mutation|fuzz|explain|verify}`.
Без `make` (например, на Windows): `python -m auditforge.cli verify` и `python -m pytest -q`.

## Закрытый прогон: защита оценщика (v1.3)

Генератор открыт, поэтому эпизод с публичным seed можно воспроизвести и прочитать его эталон. Поэтому режим `eval`
в изолированном оценщике (`RemoteEnv`) **защищён по умолчанию**:

* **Секрет всегда есть.** Если организаторы не дали свой, процесс оценщика сам создаёт случайный. `make verify` и
  `python demo.py` тоже берут случайный секрет при каждом запуске. Фиксированный секрет включается только явно
  (`AUDITFORGE_LOCAL_SECRET` для `verify`, второй аргумент `demo.py`) и не подходит для закрытого прогона.
* **Свой секрет организаторов** (чтобы закрытый прогон можно было повторить): `RemoteEnv(mode="eval", secret=...)`
  или файл, доступный только обвязке: `AUDITFORGE_SECRET_FILE=/secure/af_secret`.
* **Как секрет попадает к оценщику:** первой строкой по его stdin, до любых сообщений агента. Ни временных файлов,
  ни командной строки, ни переменных окружения (`/proc/<pid>/cmdline` и `/proc/<pid>/environ` чистые).
* **`train` не читает секрет из окружения**: код рядом с обвязкой не может открыть train-копию закрытого эпизода.
* **Режим и лимиты задаёт только тот, кто запускает оценщика** (`--mode`, `--max-steps`, `--time-limit`). `reset`
  с полями `mode` или `limits` отклоняется (`forbidden_field`). В `eval` один процесс = один эпизод (`eval_single_episode`).
* **Оценка идёт по отдельному каналу обвязки** (отдельный pipe). В `eval` запрос `evaluation` по каналу агента
  отклоняется (`harness_only`); обвязка читает итог через `RemoteEnv.evaluation()` только после конца эпизода.

Все пункты закреплены проверками в `make verify`. Числа `hidden_like` в отчёте `verify` слегка меняются от запуска
к запуску, потому что секрет случайный; таблицы train/dev ниже детерминированы.

## Типы ошибок (независимо настраиваются в `config["faults"]`)

| Тип | Что произошло | Доказательство |
|---|---|---|
| `duplicate_invoice` | повторно выставлен счёт (тот же контрагент, `po_ref`, строки в другом порядке, другой номер/дата) | оба счёта |
| `payment_allocation` | платёж распределён частично или вовсе не распределён (`invoice_refs=null`), остаток в `UNAPPLIED` | платёж + проводка `UNAPPLIED` |
| `fx_error` | неверная дата курса (UTC-дата, предыдущий день, дата счёта) или опечатка в курсе | платёж + проводка AR + запись `fx` с верным курсом |
| `period_cutoff` | проводка по другую сторону границы периода, чем документ (в часовом поясе компании) | документ + проводка |

Взаимодействующие сценарии (`config["interactions"]`):
`partial_fx` — частичное распределение платежа в другой валюте у границы периода, а курс взят по UTC-дате;
`cutoff_fx` — платёж проведён за границей периода и сконвертирован по курсу даты проведения. В `provenance.json` записана причинная связь.

Корректные отвлекающие случаи: платежи в рассрочку, возвраты, платёж на несколько счетов, повторяющиеся подписки,
одинаковые суммы с разным `po_ref`, документы у границы периода с «обманчивой» датой в чужом UTC-смещении, верные кросс-валютные платежи, авансы (платёж без счёта честно лежит в `UNAPPLIED`), частичные поставки (второй счёт по тому же `po_ref` с другими позициями, иногда на ту же сумму), поздние (5 ч – 4 дня) и ранние (до 20 ч до документа) проводки в том же периоде, авансы с `invoice_refs = null`, переплата с остатком «на счёте как предоплата» по memo.

## Метрики и награда

TP — совпадение типа, канонических `affected_ids`, суммы (допуск `policy.amount_tolerance_minor`=1), валюты и хотя бы одного
полного допустимого набора доказательств; все указанные ID доказательств должны существовать в эпизоде. Совпадение — максимальное паросочетание 1-к-1; лишние и повторные выводы — FP.
`P=TP/(TP+FP)`, `R=TP/(TP+FN)`, `F1=2TP/(2TP+FP+FN)`; на одном эпизоде при нулевом знаменателе P или R равны 0; пустой эталон и пустые выводы → F1=1; пустой эталон при выводах → F1=0.
Награда = `clip(2·F1 − 1 − 0.002·inspection_steps, −1, 1)`; неверная структура → −1.

P и R считаются по сумме всех находок и ошибок за все эпизоды, поэтому чистые эпизоды (0 ошибок) их не искажают; F1 и return усредняются по эпизодам. «—»: агент ничего не пометил, точность не определена.

`zero_agent` («всегда молчать») — диагностика, а не базовая политика: +1 на чистых эпизодах, −1 на остальных.

**Простые правила-обходы против эталона** (40 эпизодов: 10 train + 10 dev + 20 hidden_like, `make analysis`). Каждое правило читает только открытые таблицы и пропускает настоящую логику (период документа против периода проводки, сравнение позиций, memo). Законные ловушки заставляют каждое из них ошибаться; тест `tests/test_tricks.py` следит, чтобы так и оставалось:

| error type | shortcut rule | TP | FP (false accusations) | FN |
|---|---|---|---|---|
| period_cutoff | posting delay outside 0-4 h | 45 | 200 | 1 |
| period_cutoff | posting before the document or 4-24 h after it | 40 | 114 | 6 |
| duplicate_invoice | same entity + po_ref | 37 | 80 | 0 |
| duplicate_invoice | same entity + po_ref + currency + total | 37 | 40 | 0 |
| payment_allocation | refs null or sum(refs) != amount | 42 | 160 | 0 |
| payment_allocation | refs null or non-empty refs with sum != amount | 42 | 120 | 0 |

**Фаззер награды** (`make fuzz`): 3200 случайных ответов, выдано 9067 TP, нечестных наград: 0; лучшее слепое угадывание по открытым записям: -1.00; перебор seed восстанавливает эпизод без секрета: да (поэтому `eval` всегда работает с секретом), с секретом: нет.

## Что проверяется «из коробки»

* 32 проверки контракта/изоляции (включая атаки на протокол и секрет оценщика), 34 проверки награды и атак, 38 мутантов оценщика (все «убиты»), фаззер награды
  (тысячи случайных ответов, каждая выданная награда перепроверяется независимым кодом), 20 парных проверок
  (порядок, ID, часовые пояса, всё сразу) и 5 побитовых повторов seed/действий;
* сертификат на каждом эпизоде (40 эпизодов в `verify`): инварианты учёта **до** ошибок, расхождения **после** = объявленные,
  независимая достаточность доказательств, отсутствие утечек в публичные файлы.

## Limitations (честные ограничения)

* Часовые пояса — фиксированные смещения (без DST и tzdata) ради офлайн-воспроизводимости.
* План счетов и сценарии упрощены (5 счетов, один курс пары «валюта платежа → валюта счёта», нет триангуляции и налогов);
  курсы — случайное блуждание, не рынок. Это не профессиональное аудиторское заключение.
* Арифметика конвертации (`money.convert_minor`) общая у генератора и независимых проверок; остальная логика перевыведена
  отдельно, но общий округлитель остаётся единой точкой отказа — его стоит проверить внешним кодом.
* Изоляция — отдельный процесс, а не песочница: для закрытого прогона запускайте оценщик в отдельном контейнере/пользователе.
* В режиме `train` и при прямом `AuditEnv` без секрета эпизод восстановим по seed: это нужно для воспроизводимого обучения. Режим `eval` в `RemoteEnv` всегда работает с секретом.
* Агент и обвязка, запускающая `RemoteEnv`, работают в одном процессе: политика в этом процессе технически может прочитать файлы репозитория. Для настоящего закрытого прогона агент должен запускаться под другим пользователем или в отдельном контейнере.
* Лимит 60 с на эпизод — по реальным часам, зависит от железа (шаги среды дают миллисекунды).
* Базовые политики — скриптовые; мы не обучали и не оценивали никакую модель и **не заявляем** улучшений обучения.
* Протестировано на Python 3.11, 3.12 и 3.13 (только stdlib): тот же seed даёт побитово те же таблицы/truth/provenance на всех трёх версиях и при разных `PYTHONHASHSEED`. Образ Dockerfile не собирался в этой среде (нет Docker-демона и сети), сборка не проверена; команда запуска не зависит от `make`.
* Наборы `hidden_like` в репозитории — локальная имитация закрытых прогонов, а не секретные seed.
